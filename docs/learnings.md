# Team learnings

Append-only. Newest cycle at the bottom. One entry per lesson: what happened, the lesson, the rule it became, and where the evidence is (PR, commit or skill). Owner: Gabrielle (Agent Resources). Added each 3-hourly cycle via a small PR (Terry, 2026-11-07 09:57 AEDT). Times AEDT.

Do not edit past entries. If a lesson turns out wrong, add a new entry that corrects it.

## Cycle 2026-11-07 (to 09:00)

1. **Branch from a fresh main.** Cloud sessions can hold a stale or shallow `origin/main`; Gabrielle's #314 branch was cut from one and had unrelated history, caught before merge. Rule: `git fetch origin main` before branching. Evidence: #314 (merged a46cafa). Follow-up: add the line to the `precheck-loop` skill (risk 7).
2. **Report the route, not the blocker.** Naming a limit ("can't", "only", "needs Terry") without a workaround stalled work. Rule: check repo, other thread or tool, then build, before any limit goes in a reply. Evidence: `.claude/skills/workaround-first`.
3. **Reviewers cannot read CI, so the author posts the verdict.** Quinn and Jun signed with "confirm green". Rule: the PR author posts the CI verdict for the exact SHA with each review request. Evidence: `.claude/skills/review-merge-handoff` (#319).
4. **Shared curl needs `|| true`.** Quinn's catch in a status curl was copied into two workflows. Rule: status curls end `|| true` so no failure email reaches Terry. Evidence: `precheck.yml`, `relay-check.yml` on main.
5. **AX3 fit is checked before the Mac shot.** #292 failed the AX3 gate (clipped headline, missing chips, overlap). Rule: run `ax3-layout-check` first and shoot AX3 in Book, Closed portrait, Open portrait and Closed landscape. Evidence: `.claude/skills/ax3-layout-check`, `.claude/skills/five-pose-stills` (#314).
6. **Rotate the simulator with the simulator tool.** The Mac tester found `rotate right` works and the AppleScript click hangs. Rule: use the rotate action, not a click. Evidence: `five-pose-stills` step 4a (#326).
7. **Estimates carry a basis.** Estimates were guesses. Rule: cards carry est_work, est_wait and basis from the agent-estimate CLI (manual PERT if it is unavailable); "n/e" when there is no basis. Evidence: `.claude/skills/playscribe-estimate`, AGENTS.md "Estimates".
8. **Every removal or reversal needs a decision note.** On the "Also new" card the panel was removed (a84dcc5) before the original goal and alternatives were weighed, then reworked to Nadia's option B with Iris's amendments (19aeb6b, 141c0ba); the panel's origin is a614bb9 / 94b17c7. Rule (confirmed by Terry): every removal or reversal gets a decision note covering the original goal, alternatives, and pros and cons, with both product and design weighing in. Evidence: PR #320; decision note in the "Fix Also new card with no games" thread.
9. **The gate is AX5, and the size goes in the filename.** The Mac shot AX3 while labelling the stills as the AX5 gate, until 1d553d4. Rule (confirmed): the gate is AX5 (accessibility-extra-extra-extra-large) and the size is in the filename (`-ax5`). This supersedes the AX3 wording in entry 5 and in the `ax3-layout-check` and `five-pose-stills` skills; Gabrielle to update those skills in a follow-up PR. Evidence: 1d553d4.
10. **Critical thought on every decision (standing rule, Terry, 2026-11-07 10:02 AEDT).** Before and while deciding, Gabrielle and Nadia (and every agent) answer: what goal did this serve, is the goal still needed and why, what value will it deliver, is that value worth the cost (and how we define "worth"), and is there a different way to reach the same goal. If not worth it, scrap it without fear and log it here. Generalises entry 8. Every decision note outcome, including anything scrapped, is appended to this file each cycle. Evidence: Terry message cmsg_0158fPo4KUquo5U1yUvNer8v54c5VPKR2q4NHEXEYYGKZ3.

11. **r050-share: kept, with a check.** Decision note in #339 (02343b4). The share feature stays, but we now measure it: Jun's feedback watcher counts shares and each round's What to Test asks one question about sharing. Scrap trigger: no shares appear in two rounds. Lesson: keep a feature on a stated evidence test with a scrap condition, not on opinion.
12. **r060-intro-tour: changed, cheapest slice first.** Decision note in #339 (02343b4). The goal stands but the build is cut to the cheapest slice that tests it before more is built. Lesson: when the goal stands and the full build is not yet proven worth its cost, ship the smallest slice first.
13. **Check the standard-size baseline before fixing an "AX drop".** On #292 the iOS engineer moved the chips into the caption at AX5 to fix a "missing v1.1" chip. The Mac check showed v1.1 never appears in the compact landscape band at any size, so the change fixed a non-problem and made the card clip itself. It was reverted; only the chip-height fix and the VoiceOver version label were kept. Rule: before fixing something that looks missing or broken at an AX size, shoot the standard size and confirm it is present there. Evidence: PR #292; decision note `docs/decisions/ax5-hero-chips.md` (outcome: Changed).
14. **Before calling something "by design", check whether the baseline itself is clipped (corrects entry 13).** At d6483d1 the Mac showed "v1.1" does appear in Closed landscape once a card-width bug is fixed: the card was drawn wider than the pager, so the top-right overlay was off-screen at every size. The earlier "by design" conclusion in entry 13 came from a standard-size still that had the same bug. Rule: compare the card's edges to a neighbouring card's in the baseline still before concluding an element is absent by design; entry 13's advice to shoot the standard size still stands, but only a clean baseline counts. Evidence: PR #292 at d6483d1; `docs/decisions/ax5-hero-chips.md`.
15. **Check what we already have before adopting a tool.** Terry connected Claude to Xcode hoping to shorten the Mac stills loop. The Xcode MCP exposes build, tests and previews but no documented simulator control, needs a Mac, and the app has no `#Preview` blocks, while the fold harness already renders each pose at AX3 and AX5 headless. Rule: list what the current harness covers, and why it missed the bug at hand, before adding a tool; first moves are harness PNG artifacts and headless `-qaPose`. Evidence: `docs/decisions/xcode-claude-mcp-trial.md`; harness `ios/PlayscribeTests/Harness`.
16. **Say whether a date is a day or a moment, where it is stored, and format it the same way everywhere.** The KCD II 1.5.6 date read 25 Jun on the UTC runner and 26 Jun on the AEDT Mac (Quinn's calibration pair, #354); release dates are stored as noon UTC days but formatted in the device zone. Decision (Nadia, Iris's condition on relative labels): Changed, show the UTC calendar day for patch and release dates; moments on this device stay local. Evidence: `docs/decisions/release-date-timezone.md`.
17. **A fill fix that only sizes columns still leaves empty rows when sections are short; check the data shape, not just the grid maths.** Terry's Upcoming screenshots showed empty space beside short sections and an update as the Tabletop stage on a tab about unreleased games. Decision: Changed, sections are only as wide as their tiles and wrap together, and the stage fronts the soonest upcoming game. Alternatives dropped: bigger tiles, one merged grid. Evidence: `docs/decisions/upcoming-fill-and-stage.md` (#348).
18. **A store-frame set needs a leak check for real content, and its follow-ups belong in the note.** r052-store-set-content was kept (five invented games, `-qaRoute store-set`), but the PS Plus card still showed real covers until Mara caught it, and Quinn caught the sun sitting under the caption. Both were fixed and recorded as follow-ups, with a unit test that none of the invented titles resolves to a real game. Evidence: `docs/decisions/r052-store-set-content.md` (#359, #358, #361).
19. **Measure queue time before optimising job time.** The CI slowdown was runner queueing, not job time; #363 folded the UI-test compile into the unit job so a push uses one runner. Source: coordinator's account (2026-11-07 16:12 AEDT); Evidence: b0a3c2f (#363). The before/after numbers are not recorded here; the CI speed thread should add them.
20. **PRECHECK PASS proves the code compiles, not that tests pass.** `precheck.yml` runs `build-for-testing` for the app, unit tests and UI tests, and never runs them; #361 had a red unit test behind a green Precheck. Rule: after the PR opens, read the unit-test CI run for the head commit before asking for sign-off (`precheck-loop` step 5, now worded to say so). Evidence: `.github/workflows/precheck.yml` (lines 39 to 59), #361.
21. **Measure the minutes before widening a check that runs on every push.** Risk 8 asked whether Precheck should run the unit tests. Theo measured on #348: Precheck compile is 1 m 48 s; the unit build and test job is 8 m 34 s plus about 1 m 40 s for the UI build (ios.yml has since merged those into one job, #363), so adding tests would take Precheck from about 2 to about 10 minutes on every claude/** push, roughly five times the macOS runner load, duplicating what ios.yml runs when the PR opens. Decision: Kept compile-only; for a risky change run the iOS workflow by hand (`workflow_dispatch`) or open a draft PR. Revisit if more than 1 in 4 of the last 20 PRs fail unit tests that Precheck could have caught. This also supplies the numbers entry 19 lacked. Evidence: `docs/decisions/precheck-unit-tests.md` (#365).
22. **When data is missing, keep the history and withhold the claim; do not hide the record.** Valheim's 2021 patch showed "On PS5" before the game had a PS5 release. Hiding pre-launch patches was rejected because it would hide real updates whenever a PS5 row is missing. Decision (Nadia): Changed, a release with no PS5 row is `.pending`, kept in history, never unread and never alerted. Caveat recorded in the note: checked by reading code and unit tests, not a feed run; gate is Priya's feed check (post-launch Steam patches with no PS5 row must be 0) before the 0.5.2 TestFlight build. Evidence: `docs/decisions/prelaunch-not-ps5.md` (#248, #366).
